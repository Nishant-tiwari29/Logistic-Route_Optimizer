Intelligent Logistics & Vehicle Routing Optimizer 2.0

A delivery planner that decides who delivers what, in which order, on which road, using graph algorithms, dynamic programming and machine learning.

See how it works Try the live demos

The problem: a short route is not always a good route

Imagine 3 warehouses, 20 customers and 5 vehicles. Someone has to answer five questions every day.

  1. 1Which depot should serve each customer?
  2. 2Which packages go into which vehicle?
  3. 3In what order should each vehicle visit its stops?
  4. 4Which plan costs less and still arrives on time?
  5. 5What if a road closes or a vehicle breaks down?

Too many choices

Just ordering 10 stops has over 3.6 million possible orders. Humans cannot check them all.

Hard rules

Vehicles have capacity limits and customers have deadlines. A plan that breaks a rule is useless.

Changing roads

Traffic changes travel time through the day, so yesterday's best route may be today's worst.

Our answer: turn the roads into a graph, let machine learning estimate travel times, let algorithms choose the plan, and check every plan against the rules.

Step 6 · Route order

Why the nearest stop is not always best

A van must visit every customer and return to the depot. A simple "go to the nearest customer" rule is compared with the exact answer from bitmask dynamic programming.

Bitmask view of the optimal route

One bit per customer: 1 means "already visited". The DP stores the best cost for every such set, so it never repeats work.

The algorithm toolbox

Different problems and different sizes need different tools. Exact tools guarantee the best answer; Heuristic tools are fast and good, with no guarantee.

Exact

Dijkstra

Cheapest path from one place to all others (non-negative weights).

O((V+E) log V)

Exact

A* search

Dijkstra with a compass: a heuristic guides the search toward the target.

Depends on heuristic

Exact

Floyd-Warshall

All pairs of places at once. Good for small networks.

O(V³)

Exact

Bitmask DP

Best stop order for small routes by remembering visited sets.

O(n²·2ⁿ)

Exact

2D Knapsack DP

Which packages fit by weight and volume.

O(N·W·V)

Exact*

Branch & Bound

Searches routes but drops any branch that cannot beat the best so far.

Worst case O(n!)

Heuristic

Clarke-Wright

Starts with one route per customer, then merges routes that save the most distance.

Fast, not optimal

Heuristic

2-Opt

Swaps two roads to remove detours from an existing route.

Local optimum

* Exact only when the search is exhaustive enough to prove optimality.

Viva questions, answered simply

Why use a graph?

Roads connect places with a cost (distance or time). A graph stores exactly that, so path algorithms can search it.

Why Dijkstra and also A*?

Dijkstra finds cheapest paths from one place to everywhere. A* is faster for one start and one target because its heuristic steers the search.

Why bitmask DP?

The best way to finish a route depends only on which customers are visited and where you are. Storing that as a bitmask lets us reuse sub-answers: exact, but exponential, so only for small routes.

Why also Clarke-Wright and 2-Opt?

Exact methods get too slow as customers grow. These give good routes quickly and can be compared against the exact answer on small cases.

Why combine ML and DSA?

ML estimates a changing number (travel time). Graph algorithms use that number to compute paths. The optimizer then coordinates all deliveries and rules.

Why C++ if the backend is Python?

C++ can speed up selected heavy algorithms such as bitmask DP. Python handles APIs, validation, ML and orchestration.

How do you prove correctness?

Automated tests, comparison with brute force on small cases, and reproducible benchmarks. This shows correctness on tested cases, not for every possible input.
